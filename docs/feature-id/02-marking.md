# 2. 코드에 표식 달기

기능을 그리는 JSX 요소에 `data-feature` 속성을 답니다. 요소를 감싸지 않고, 이미 있는 요소에 속성만 추가합니다.

```tsx
<section data-feature="F-0009" aria-label="상품 랭킹">…</section>   // DOM 요소
<TabBar data-feature="F-0024" tabs={…} />                          // 컴포넌트
<div data-feature={['F-0017', 'F-0019']}>…</div>                   // 기능 여럿
```

- **그 요소의 여는 태그부터 닫는 태그까지**가 그 기능의 범위입니다. 이 범위 안이 바뀌면 그 기능을 건드린 것으로 계산됩니다.
- 컴포넌트의 props 타입을 고칠 필요가 없습니다. 모든 JSX 요소에 달 수 있습니다.
- 없는 ID, 오타, 중·대분류 ID는 타입 에러가 납니다.
- 속성 이름은 `id`가 아닙니다. HTML `id`(aria 연결에 쓰임)와 겹치기 때문입니다.

## 어디에 달까요

**그 기능만 담는 가장 높은 요소**에 답니다. 아래 순서대로 고르세요.

| 순서 | 상황                                        | 다는 곳                                       | 실제 예                                                                          |
| ---- | ------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------- |
| 1    | `features/` 컴포넌트가 **기능 하나만** 그림 | 그 컴포넌트의 **루트 요소**                   | `ProductRankingSection`의 `<section>` → `F-0009`                                 |
| 2    | `features/` 컴포넌트가 **기능 여럿을** 그림 | 컴포넌트 **안에서** 기능별 요소로 나눠서      | `BrandHomeHero`: `<header>` → `F-0154`, 정보 영역 → `F-0150`, 평점 줄 → `F-0151` |
| 3    | **페이지 전체가** 기능 하나                 | 페이지 컴포넌트의 루트 요소                   | `GenderPage`의 루트 `<div>` → `F-0070`                                           |
| 4    | `shared/` 컴포넌트                          | **안에 달지 않습니다.** 쓰는 쪽 요소에 답니다 | `MyPage`에서 `<InfoRow data-feature="F-0065" label="1:1 문의" />`                |

### 왜 이 순서인가요

- **컴포넌트 안에 달면** 그 컴포넌트를 어디로 옮겨도 표식이 같이 따라갑니다.
  컴포넌트 안에 단 표식은 그 컴포넌트를 렌더하는 줄(예: 페이지의 `<ProductRankingSection />`)까지 같은 기능으로 계산됩니다.
  그래서 페이지에서 순서나 props를 바꿔도 놓치지 않습니다.
- **`shared/` 안에 달면 안 되는 이유:** `HorizontalCategoriesTab`은 5.2.1 소분류 탭에도, 8.5.1 크리에이터 리뷰에도 쓰입니다.
  안에 한 기능을 적으면 다른 곳에서 쓸 때 틀린 기능으로 계산됩니다.

## 자주 만나는 경우

### 루트가 Fragment(`<>`)일 때

Fragment에는 속성을 달 수 없습니다. 형제 요소마다 같은 ID를 답니다. 범위는 둘을 합친 것으로 계산됩니다.

```tsx
// BrandProductList.tsx
<>
  <ul data-feature="F-0153" aria-label="브랜드 상품 목록">
    …
  </ul>
  <div data-feature="F-0153" ref={loadMoreRef}>
    …
  </div>
</>
```

### 로딩·에러로 일찍 return할 때

마지막 return(본 화면)의 루트에만 달면 됩니다.
같은 컴포넌트 함수 안의 다른 분기(로딩·에러·빈 화면)도 그 기능으로 계산됩니다.

### 떼어 낼 수 없는 기능

카드를 눌러 상세로 이동하는 기능(예: 3.1.3)은 `shared/` 카드 안에 있어서 목록과 따로 표시할 수 없습니다.
이럴 때는 목록에 **함께** 답니다.

```tsx
// ProductRankingsSection.tsx — 3.1.1 목록 + 3.1.3 상세로 이동
<div data-feature={['F-0017', 'F-0019']}>…</div>
```

이렇게 기능 여럿을 단 범위가 바뀌면 PR에서 `possible`(사람이 확인)로 나옵니다.
정확히 나뉘길 원하면 기능별 요소로 나눠 다는 게 좋습니다.

### 달지 않는 기능

자기 화면 요소가 없는 기능은 달지 않습니다.

- 서버에서 처리하는 기능 (예: 9.1.3 브랜드와 제품 별칭 검색)
- 아직 구현되지 않은 기능 (예: 12.4.2 회원가입 완료 토스트)
- 여러 화면에 걸친 공통 규칙 (예: 6.6.3 리뷰 카드 제시 방식)

## 하지 말아야 할 것

| 하지 마세요                               | 이유                                                                                                  |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `data-feature="3.3.1"` (표시 번호)        | 번호는 바뀝니다. 타입 에러도 납니다 → [Cmd + .로 바꾸기](./03-editor.md#표시-번호를-기능-id로-바꾸기) |
| `shared/` 컴포넌트 안에 달기              | 다른 화면에서 쓸 때 틀린 기능으로 계산됩니다                                                          |
| 진행 단계(`done`, `screen`)를 코드에 적기 | 연결 상태가 바뀌면 거짓 정보가 됩니다. 단계는 PR 주석에만 씁니다                                      |
| 주석(`{/* F-0024 */}`)으로 적기           | 범위를 알 수 없고 타입 검사도 되지 않습니다                                                           |

## 참고

DOM 요소에 단 값은 브라우저 HTML에도 그대로 남습니다 (`<div data-feature="F-0164">`).
민감한 정보는 아니며, 개발자 도구에서 어떤 기능인지 바로 확인할 때 쓸 수 있습니다.
