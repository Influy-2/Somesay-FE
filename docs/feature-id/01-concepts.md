# 1. 기능 ID와 표시 번호

팀웹의 기능에는 번호가 두 가지 붙습니다. 둘을 헷갈리면 안 됩니다.

| 이름          | 예       | 바뀌나요?                                                            | 어디에 쓰나요                  |
| ------------- | -------- | -------------------------------------------------------------------- | ------------------------------ |
| **기능 ID**   | `F-0024` | **절대 바뀌지 않습니다.** 기능을 지워도 그 번호를 다시 쓰지 않습니다 | 코드 (`data-feature`)          |
| **표시 번호** | `3.3.1`  | 기획이 기능을 옮기거나 순서를 바꾸면 **바뀝니다**                    | 사람이 읽는 곳 (PR 본문, 대화) |

## 왜 코드에는 기능 ID만 쓰나요

예전에는 코드 주석에 `@spec 2.3.1`처럼 표시 번호를 적었습니다.
기획이 "AI 추천 검색"을 2번 대분류로 끼워 넣자 랭킹이 2번에서 3번으로 밀렸고, 페이지 파일 32개를 고쳐야 했습니다.
고치는 과정에서 번호가 틀린 채 남은 곳도 생겼습니다.

기능 ID는 바뀌지 않으므로 기획이 순서를 바꿔도 코드는 그대로입니다.

## 사람에게 보여 줄 때는

표시 번호와 제목을 같이 씁니다. 기능 ID는 괄호에 넣어 둡니다.

```
3.3.1 상단 탭 전환 (F-0024)
```

PR 본문과 팀웹 진행 주석(`<!-- team-web: 3.3.1:done -->`)에는 **PR을 쓰는 시점의** 표시 번호를 씁니다.

## 단계 구분

표시 번호는 대분류(`3`) › 중분류(`3.3`) › 소분류(`3.3.1`) 세 단계입니다.
**코드에는 소분류 기능 ID만** 달 수 있습니다. 팀웹이 진행 상황을 소분류 단위로 기록하기 때문입니다.
중분류·대분류 ID(`F-0023`, `F-0015`)를 달면 타입 에러가 납니다.

## 목록은 어디에 있나요

- 원본: 팀웹 기능 목록
- 레포의 복사본: [`packages/shared/features/features.json`](../../packages/shared/features/features.json)
  (`id` · `display_no` · `title`). 기능 ID ↔ 표시 번호를 찾을 때 이 파일을 보면 됩니다.
- 목록이 바뀌면 복사본을 갱신합니다 → [4. 기능 목록 갱신과 PR 작성](./04-workflow.md#기능-목록-갱신)
